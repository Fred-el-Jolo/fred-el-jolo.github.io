    Talk given at JSSophia on 14 March 2019. A walkthrough of asynchronous JavaScript patterns, from callback hell to generators and async/await.

    Agenda

    1. Sync vs Async
    2. Callbacks
    3. Promises
    4. Generators
    5. Async/Await

    Sync vs Async

    High-level thinking is single-threaded. The browser's event loop is also single-threaded — a blocking operation halts everything.

    The event loop is a FIFO queue: functions sit on the call stack, objects in the heap, and pending messages in the queue. Queue messages are processed only when the stack is empty.

    Blocking the event loop

    const end = Date.now() + 5000;
while (Date.now() < end) {
  // Expensive operation — blocks the entire event loop
}

    Beware of: expensive regex, JSON.parse / JSON.stringify on large payloads, synchronous crypto.

    Callbacks

    Callbacks defer execution until an async operation completes — but pass control to third-party code (inversion of control).

    Callback hell

    api.getUser(login, function(err, user) {
  api.getGeoLocation(user, function(err, location) {
    api.getWeather(location, function(err, weather) {
      api.notifyWeather(weather, function(err, data) {
        // deeply nested, tightly coupled
      });
    });
  });
});

    Problems: execution timing (too early, too late, never, too many times), error management (try/catch doesn't catch async errors), tightly coupled code.

    Partial solutions

    // Split callbacks
async(source, successCallback, errorCallback);

// Error-first (Node.js style)
async(source, function(err, data) { /* ... */ });

    Promises

    Promises uninvert the inversion of control — you get back a value that represents a future result, rather than handing your callback to someone else.

    Flow control

    promise.then(
  function() { /* fulfilled */ },
  function() { /* rejected */ }
);

    Promisifying a callback API

    function asyncPromisified(data) {
  return new Promise(function(resolve, reject) {
    async(data, function(err, data) {
      err ? reject(err) : resolve(data);
    });
  });
}

    Promise guarantees

    • Always called asynchronously (even if resolved synchronously)
    • Called at most once
    • Immutable once resolved
    • Promise.resolve always returns a genuine trustable promise

    Promise patterns

    • Promise.all([]) — fulfilled only when all resolve; rejected immediately if any rejects
    • Promise.race([]) — settled by whichever promise settles first

    Promise limitations

    • Errors can be silently swallowed inside a chain
    • Single value parameter
    • Only one resolution (no repeated events)
    • Cannot be cancelled

    Generators

    Generators express async flow in a sequential style using yield. A generator function returns an iterator; each next() call runs until the next yield.

    Yielding a promise lets you pause the generator and resume it when the promise resolves — the conceptual bridge to async/await.

    Async/Await

    Syntactic sugar over generators + promises. Async control flow written in a sequential, readable style.

    async function fetchUserWeather(login) {
  try {
    const user     = await api.getUser(login);
    const location = await api.getGeoLocation(user);
    const weather  = await api.getWeather(location);
    return weather;
  } catch (err) {
    console.error(err);
  }
}

    Remaining limitations (vs callbacks)

    • Single value parameter
    • Only single resolution
    • Cannot be cancelled
